ApeMe Build Plan
ApeMe · apeme.fun · build plan

Six phases, indexer first, nothing waits

The indexer is phase 0 because it is the product. Every screen is built in parallel against a fixed contract, so nothing waits on it, and nothing is built on top of it.

Nine days from Wednesday 16 Sep. Two lanes run at once: backend on the VPS and Cloudflare, app on the Mac. If a phase slips, the ones after it still ship, because every one has a fallback written down.

rule 1

Contract on the first morning

Before the indexer gets a line of code, the schema, the Event shape and every endpoint's JSON shape are written, and the Worker serves fake data for all of them. Two hours. The app builds every screen against that. Real data replaces fake underneath without the app changing.

rule 2

Indexer first, but nothing on top of it

The stream is built first because it is the beef. But every number also has a polled source from public APIs, so if the stream slips, screens go live on time and just run 5 seconds behind until it catches up.

rule 3

Every phase has a demo

A phase is done when the thing it ships can be opened on a phone or hit with curl and shown to someone. Not when the code is written.

The phases

phase 0

The indexer

Wed 16 to Fri 18 · 3 days
shipsA StonkFun or pump.fun trade lands in our database under a second after it lands on chain, decoded into the two primitives, with a health route showing slot lag. This is the beef. Everything else is a skin on it.
backend, Wed morning, before any code
  • D1 schema: stocks, tokens, pools, trades, candles_1m, token_stats, cursor
  • The Event shape: PoolCreated and Swap, fields fixed
  • API contract and fixture JSON for every endpoint, served behind a mock flag. Two hours. This is what lets the app lane run without waiting
backend, Wed to Thu · decoders
  • Generic Anchor event decoder, emit_cpi tag and discriminator lookup from the six IDLs
  • Six adapters to PoolCreated and Swap. LaunchLab and DBC pull quote mint and payer from accounts. CPMM from accounts plus balance delta
  • Fixtures: 8 real transactions per program saved as JSON, tests green
backend, Thu to Fri · stream
  • Yellowstone client on Nexus, one stream per program, source filter with the stock mint list, proven live
  • Batch every 500ms, sign, post to Ingest. Cursor by slot, replay on restart
  • Ingest on the Worker: dedupe by signature, upsert token and pool on PoolCreated, insert trade, fold candle, bump stats
  • systemd unit, health route, alert on silence
app, same three days, on mocks
  • Xcode project, SwiftUI shell, three tabs, API client from the contract
  • Privy SDK, login screen
  • Stocks screen and memes-for-stock screen on fixture data
  • Token page: Canvas candle chart, trade tape on a fixture WebSocket
  • By Friday night every screen exists and works on fake data
needsthe five data decisions, the Nexus key, VPS access
unblocksphase 1 reads what this writes
if it slipsphase 1 has a polled fallback for every number, so screens still go live on time, just 5 seconds behind
phase 1

Real data on every screen

Sat 19 · 1 day
shipsScreens 1, 2 and 3 with real data, mock flag off. Every stock token, every stonk meme under its stock, the token page live from the indexer.
backend
  • Stocks poller: StonkFun quote-tokens into stocks. Tessera valuations only if time at the end
  • Backfill: LaunchLab list by both StonkFun platform ids, pump.fun coins by quote mint, historical curve trades from the LaunchLab history API. Everything launched before the stream started
  • Snapshot cron: DexScreener into token_stats and KV
  • Endpoints on real tables: stocks, memes by stock, token, trades, candles
  • Live room per token fed by Ingest. Floor room with 2-second diffs
app
  • Flip the base URL from mock to real. That is the whole change
  • Fix what real data breaks: long names, empty states, thousands of rows
needsphase 0 schema. The stream if it is up, polling if not
unblocksphases 3 and 4 read the catalog
if the stream is not uptrades and candles come from the LaunchLab history API and GeckoTerminal, 5 seconds behind, same endpoints
phase 2

The ape

Sun 20 · 1 day
shipsA real buy on mainnet from the phone. Tap Ape, preset amount, signed on device, confirmed, position badge on the card, fee row in the ledger.
backend
  • Quote endpoint: Jupiter quote with the 1% fee parameter and our referral account
  • Ape endpoint: takes signed bytes, broadcasts through Nexus RPC with priority, records the fee row
  • Me endpoint: balances by RPC, positions from our trades table
app
  • Ape sheet: amount presets, quote, one tap
  • Privy signing on device, no popup
  • Confirmation state, error states, position badge
needsthe contract, a Privy app id, a Jupiter referral account. Not the indexer
unblocksphase 4 pushes need an Ape button to land on
if it slipsbalances come from RPC, nothing here touches the stream. If Privy is late, Phantom deep link as the stopgap
phase 3

Meteora DBC, the bounty target

Mon 21 · 1 day
shipsA DBC view inside the app that nobody else has: every stock-quoted DBC pool on Solana, the curve drawn from its config, progress to the migration threshold, the fee schedule, and where it graduates to. Working on mainnet, which is what Meteora asked for over slides.
backend
  • The indexer already streams every stock-quoted DBC pool from phase 0, so the list exists
  • Meteora DBC SDK reads each pool's config and state: curve points, quote reserve, migration threshold, fee scheduler, migration target DAMM v1 or v2
  • Endpoint per DBC pool: curve shape, progress, fees, next fee step, graduation ETA from recent volume
  • Config comparison: which DBC configs are used for stock pairs, grouped by fee and threshold, so an issuer can see what works
app
  • DBC filter on the memes screen and a DBC badge on cards
  • Token page for a DBC pool: the curve drawn on Canvas with the current point marked, progress bar to migration, fee line
  • A small "DBC pools" section with the config comparison
needsphase 0 stream on DBC, phase 1 catalog
unblocksnothing, it is leaf work
if it slipsthe list and progress bar ship from indexer data alone, the curve drawing and config comparison follow
phase 4

KOL calls, first version

Tue 22 · 1 day
shipsA tracked X account posts about a token we index, everyone watching them gets a push with an Ape button within two minutes, and the call is pinned on the chart at the price it was posted.
backend
  • X reader cron, 20 seed handles, since last id
  • Classifier: cashtag, mint, ticker, launch link, against the catalog
  • Calls table with price at post, callouts endpoint per token
  • Queue to APNs with an Ape action
  • Fee ledger credits 0.3% to the called handle on apes from the push
app
  • KOL watchlist screen, add by handle
  • Push handling, deep link into the ape sheet
  • Callout avatars pinned on the chart, callouts feed with return since call
needsphase 1 catalog, phase 2 for the Ape action, an X developer account with a card, an APNs key
unblocksnothing
if it slipsit is the last feature in, the submission stands without it
phase 5

Break it, then ship it

Wed 23 to Thu 24 · 2 days
shipsA TestFlight build ten people have traded on, a three-minute video, a README, and the submission form filled for the main track and Meteora DBC, plus Tessera only if it got done, a day before the deadline.
backend
  • Kill the VPS, kill Nexus, kill a data API, one at a time. Fix anything that takes a screen down
  • Rate limit checks against the free tiers under ten users
  • README with architecture, the verification sheet, how to run
app
  • TestFlight group of ten, collect what confused them, fix the top three
  • Record the video on device: open Nvidia, tap a meme, ape, see it land, open a DBC pool and its curve, get a call, ape from the push
  • Submit
needsphases 0 to 2 at minimum
unblocksthe submission
if it slipssubmit Wednesday night with what works, edits are allowed until close
